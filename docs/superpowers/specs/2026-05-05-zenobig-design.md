# Zenobig Studio Website Design

## Goal

Create a new multi-page studio website for Zenobig that feels structurally different from the existing MySkyrs, BreadsBasket, SingularityLaber, and EchoLogicer sites. The studio focuses on mobile software development and IAA advertising monetization, but the site should avoid the familiar "agency hero plus card grid" pattern.

## Brand Direction

- Brand: Zenobig
- Positioning: mobile software studio building utility products, lightweight consumer releases, and IAA-supported revenue systems
- Contact addresses:
  - support@zenobig.com
  - business@zenobig.com
  - vip@zenobig.com

## Visual Direction

Zenobig will use an "archive / field manual" visual language instead of a traditional business homepage.

- Bright paper-like background with heavy charcoal typography
- Sharp accent color used sparingly for markers, dividers, labels, and calls to action
- Large editorial headlines and compressed micro-labels
- Non-symmetrical layout blocks, horizontal dividers, numbered sections, and poster-like spacing
- Fewer rounded cards, more rails, columns, data strips, and dossier-like panels

## Structural Differences

The new site should break from the existing family of studio pages by changing the information rhythm.

- Homepage opens with an editorial masthead and chapter list instead of a standard corporate hero
- Sections are organized like a field manual: brief, chapter, system, release, support
- Pages use more text-led composition and fewer repetitive feature card grids
- Navigation labels shift away from generic "About / Services / Portfolio"

## Site Map

- `index.html` - homepage / studio brief
- `practice.html` - how the studio works
- `systems.html` - mobile product and build systems
- `revenue.html` - IAA monetization model
- `contact.html` - public contact routes
- `privacy.html` - detailed privacy policy
- `support.html` - end-user support and FAQ

## Content Priorities

- Make the studio feel real and intentional
- Explain mobile software development in practical, non-generic language
- Present IAA monetization as part of product operations rather than a buzzword
- Keep privacy and support pages complete enough for public trust and store review context

## Testing Strategy

- Static file test suite verifies all pages exist
- Shared asset references remain consistent
- Homepage includes Zenobig plus mobile software and IAA framing
- Contact/support/privacy pages include the provided email addresses
- Page navigation covers the full new page set
